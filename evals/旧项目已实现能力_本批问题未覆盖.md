# 旧项目已实现能力中，本批问法未单独覆盖的测试题

依据旧项目 `PRD.md`、`anomaly_report.py`、`main.py` 的**实际实现**列题。用户给出的自然语言问题在本项目被拆成 14 个评测场景；下表只列本批没有独立检验的旧能力。旧项目只有 CPS 与安全过件率决定报告模板；其余 8 个指标主要用于状态展示或结果指标异常后的拆解，不应误写成独立告警能力。

| 建议新增问题 / 测试情形 | 旧项目实际能做什么 | 验收时特别注意 |
|---|---|---|
| “今天腾讯 CPS 和安全过件率**同时**异常，报告会怎样判断？” | 走双异常模板 D，同时展示成本拆解、安全过件率排查 | 旧实现把“计费比超标”写死；此题应测新产品能否避免抖音和计费比正常时的错误归因 |
| “CPS 恶化时，cpcl、授信成本、授信单产、平均额度、动支率、额度使用率各处在什么状态？” | 成本异常模板展示三层过程指标及固定阈值状态 | 本批 A1 只检验成本／单产贡献，C1 检验质量价值权衡；没有完整检验旧产品的三层指标展示 |
| “大盘 CPS 已异动，究竟是腾讯哪种出价方式／版位，或抖音哪个账户组拖累？” | 主渠道异动后拉取分组卡片，在仅部分组异常时定位 | 本批 B2 问的是**大盘正常但局部差**，恰好不满足旧实现的下钻触发条件 |
| “安全过件率越线但 CPS 正常，腾讯计费比高／正常各如何排查？抖音怎么办？” | 进入质量异常模板；腾讯按计费比分支，抖音不使用计费比 | 本批 C2 的前提实际不成立，没覆盖两个计费比分支及抖音差异；旧项目以计费比定内外责任过于绝对，不能照搬结论 |
| “CPS 或安全过件率看着异常，但当次首借／申完样本量不足，是否仍应建议动作？” | 指标显示“异动但数据不足”的黄色状态 | 旧实现报告分支不总是使用置信条件，可能仍给动作；新产品需测正确降级，而非照搬这个缺陷 |
| “一个渠道关键字段缺失、另一个渠道完整，是否还能生成可靠报告？” | `main.py` 对缺关键字段的渠道跳过，另一渠道继续 | 本批 D2 测跨表数据可信度，没有测取数缺字段的熔断 |
| “今天两渠道均正常，该发什么报告？” | 模板 A 输出简报；旧项目有定时推送和预览模式 | 本批均为异常或诊断提问，未测正常日不夸大异常的行为 |

**产品形态另需单测**：旧项目每天 7 次定时取数与推送、同一时段防重复、多群分发和预览模式。它们不是业务问答题；当前 14 个独立会话评测未覆盖这类主动告警与交付流程。旧项目本身的 T 日口径、样本门槛和固定阈值也有缺陷，因此应把这些题作为能力覆盖测试，而不是把旧答案当作标准答案。

## 旧生成器实跑核对

将 `03_模拟数据_补充/ads_rta_legacy_alert_cases.csv` 的 8 个完整样本换算为旧 `anomaly_report.generate` 所需的指标，并把双异常的分组样本传入下钻参数，8 个样本均成功生成报告。正常、双异常、低单产、质量异常且腾讯计费比高／正常、抖音质量异常和小样本分支均有可观察输出。实跑也复现了两项已知缺陷：`SIM_DUAL_DY` 的报告错误地写出“计费比超标”；`SIM_LOW_SAMPLE` 虽标成“不置信”，仍给出媒体侧动作建议。`SIM_MISSING_AMOUNT` 同时缺首借金额和旧卡片关键字段 CPS，按 `main.py` 的关键字段检查应跳过；报告生成器不能直接把缺失值代入 0。本次未连接观远卡片或推送服务，所以该场景的端到端熔断仍待集成测试。
