# 01 业务背景

> 本文件属于竞品测试模拟环境的知识库，供被测产品加载。
> 本文描述的是一个**模拟业务世界**，其中所有数值、账户、主体均为构造，不对应任何真实公司、真实账户或真实客户。
> 标记说明：【模拟设定】= 本环境自定义；【源资料未确认】= 源知识库中没有足够依据、本环境不做断言。来自异动分析产品的固定阈值与归因分支属于**产品现状**，不等于已验证的业务因果。

---

## 一、这个业务在做什么

这是一条**信贷类 App 的信息流获客业务线**。业务方通过媒体（抖音、腾讯）投放信息流广告，把用户引导到自家信贷 App / 小程序，再完成申请、授信、动支（借款）等后端流程。

与普通效果广告最大的区别：

| | 普通效果广告 | 本业务 |
|---|---|---|
| 转化终点 | 点击 / 下载 / 注册 | **动支（成功借款）** 及其后的交易金额 |
| 是否只看量 | 是 | 否，必须同时看**成本、规模、质量** |
| 后端环节 | 基本没有 | 申完 → 授信 → 发起 → 动支 → 还款；安全授信是授信户中的 A 卡前 3 组 |
| 风险约束 | 无 | 有。**不是用户来了就算成功**，还要看他能不能授信、愿不愿意借、借了还不还 |

一句话概括业务目标：

> **在转化效率和风险质量的约束下，用尽可能低的成本，拿到尽可能多的高价值目标客户。**

## 二、三类互相牵制的目标

业务方同时背着三件事，而这三点天然冲突：

| 目标 | 业务含义 | 主要指标 |
|---|---|---|
| **降本** | 用更低成本拿到目标转化 | CPS、cpcl、授信成本、首登成本 |
| **增量** | 拿到更大规模的新客与交易 | 花费、首登量、申完量、授信量、首借金额 |
| **提质** | 拿到更优质、更安全、更高价值的客户 | 安全过件率、安全交易占比、首借单产、Vintage30 逾期率 |

**降本容易带来质量塌陷，放量容易带来成本失控。** 这三者之间的取舍是本业务日常决策的主线，也是本环境全部 Showcase 的底层背景。

## 三、渠道角色分工

本环境包含两个媒体渠道，**两者的业务特征明显不同**，这是很多分析结论必须分渠道给出的原因。

| 维度 | 腾讯（广点通） | 抖音（巨量引擎） |
|---|---|---|
| 流量性质 | 版位分散、人群泛、意图相对弱 | 内容流强跳转、人群意图相对强 |
| 首登规模 | 本环境稳定期约 720/日 | 本环境稳定期约 836/日 |
| 首登 → 申完 转化率 | 低 | 高 |
| 平均授信额度 | 高 | 低 |
| 安全过件率 | 本环境稳定期约 19.4% | 本环境稳定期约 21.9% |
| 授信成本 | 高 | 低 |
| 计费比口径 | **适用** | **不适用**（见 04 文档） |
| 主要风险 | 承接链路效率、成本 | 流量质量波动、规模不稳 |

【模拟设定】本环境**保留**“计费比对抖音不适用”的口径差异。腾讯侧的计费比也只用于初筛；本环境的基础出价口径不能代替真实投放的实际 Bid（见 04 文档第三节）。

## 四、RTA 在投放链路中的位置

RTA（Real-Time API）是媒体广告请求链路上的**实时接口能力**：媒体在每一次广告请求中把待评估的设备信息下发给业务方，业务方在极短时间内（毫秒级）判断"这个用户要不要参竞、出价多少"，把结果回给媒体。

完整链路：

```text
请求 → 出价 → 竞得 → 曝光 → 点击 → 首登 → 申完 → 授信/安全 → 发起 → 动支 → 还款/逾期
  ↑                                    ↑
  └─ RTA 在这里介入                    └─ 产品侧通常从这里开始观测
```

RTA 的两类策略：

| 策略 | 作用 | 例子 |
|---|---|---|
| **排除策略** | 对高风险、低转化、低价值用户拒绝参竞 | 返回出价 0 或不参竞 |
| **出价策略** | 对不同价值客群动态设置价格 | 高质量高意愿用户高出价，反之低出价 |

**关键机制**：出价策略最终落在 `基础出价 × preA系数 × preG系数` 的二维出价系数表上（详见 04 文档）。因此**"RTA 策略"这个维度，本质上是 RTA 策略在投放侧的可观测投影**——某个 RTA 策略表现变差，往往等价于"某一段 W/Q 组合出了问题"。

## 五、参与团队与职责

| 角色 | 关心什么 | 典型动作 |
|---|---|---|
| **获客运营** | 今天要不要介入、介入什么 | 调预算、调出价、暂停/恢复投放 |
| **获客策略** | RTA 排除、出价系数、回传口径是否需要调整 | 改排除包、改系数表、改回传配置 |
| **获客模型** | preA/preG 模型分是否稳定、是否需要迭代 | 模型版本更新、特征调整 |
| **渠道对接人** | 是否需要联动媒体排查 | 向媒体发起定向/流量核查 |
| **风险 / 资金 / 产品** | 授信后变现环节是否出问题 | 审批口径、资金路由、申请流程 |
| **数据 / 研发** | 回传链路、转化漏斗、埋点是否异常 | 链路排查、数据修复 |
| **素材** | 素材供给与迭代 | 新素材上线、老素材下线 |

【源资料未确认】真实业务中还存在**代理**这一执行环节（代理决策代理执行 / 业务方决策代理执行 / 业务方决策系统执行三种账户模式）。本模拟环境**不包含代理角色**，账号统一视为业务方直控。这是已知的简化，不构成对真实业务结构的断言。

## 六、哪些动作必须人工确认

本业务**不做自动执行**。任何影响投放的动作都要经过人工确认：

| 动作类型 | 是否自动 | 说明 |
|---|---|---|
| 判定异常 | ✅ 系统可自动 | 阈值 + 样本量门槛 |
| 定位环节 | ✅ 系统可自动 | 依恒等式逐层拆解 |
| 给出建议 | ✅ 系统可自动 | 结论 + 建议动作 + 责任方 |
| **调整预算 / 出价** | ❌ 人工确认 | 影响成本与规模，不可逆性高 |
| **暂停或关闭投放** | ❌ 人工确认 | 影响规模，需评估机会成本 |
| **修改排除包 / 系数表 / 回传配置** | ❌ 人工确认 | 影响后续人群结构，且有实验污染风险 |
| **回滚策略变更** | ❌ 人工确认 | 需先判断变化是"异常"还是"策略意图" |

> ⚠️ **一条重要的产品原则**：**并非所有指标下降都等于异常。** 如果是我方主动收紧风控导致的"安全过件率下降"，那是策略意图，不应作为异常处置。判断"不做什么"与判断"做什么"同等重要。

## 七、业务当前面对的结构性压力

以下是本次模拟环境设定的背景（部分取自源知识库中组织自述的长期趋势，部分为本环境设定）：

| # | 压力 | 对本环境的意义 |
|---|---|---|
| 1 | 流量质量存在长期下行趋势 | "质量下降"有时是基线漂移而非异常 |
| 2 | 抖音侧规模波动较大 | 抖音的规模问题需要与成本问题分开看 |
| 3 | 腾讯侧存在无负向干预下的质量下滑 | 需要区分"我方动作"与"环境变化" |
| 4 | 资信调用成本需要压降 | 降本与提质压力同时存在 |
