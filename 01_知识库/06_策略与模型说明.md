# 06 策略与模型说明

> 本文件说明"哪些指标是我方可控动作的结果"。**分析得出结论后，必须能回答"这个结论对应哪个可执行动作、谁负责"。**

---

## 一、模型体系概览

获客侧以**转化、质量两类核心模型**支撑 RTA 决策；另有服务媒体学习的回传模型：

| 能力层 | 典型模型 | 解决的问题 | 服务的策略动作 |
|---|---|---|---|
| **转化模型** | 转化主模型、后端意愿模型 | 谁更可能从曝光继续走到申完、授信、动支 | 决定 preG（意愿层 W） |
| **质量模型** | 质量前筛、排黑、质量主模型、资质模型 | 谁更安全、更可能通过审批、更具长期价值 | 决定 preA（质量层 Q） |
| **回传模型** | 首借动支模型、首借单产模型 | 哪些用户应被定义为"更有价值样本"反馈给媒体 | 决定回传谁、回传什么 |

**三个模型的分工一句话**：

```text
转化模型  →  谁愿意借          （W 层）
质量模型  →  谁借了还得上      （Q 层）
回传模型  →  该让媒体学习谁     （回传决策）
```

### 1.1 模型输出如何影响投放

```text
用户请求
   ↓
preG 模型（意愿）→ W 档位
preA 模型（质量）→ Q 档位
   ↓
W × Q 二维系数表 → 出价系数
   ↓
最终出价 = 基础出价 × 系数
   ↓
影响 eCPM、参竞、曝光结构
```

> ⭐ **因此"模型分退化"会直接改变进入的人群结构**，进而影响安全过件率与授信单产。**这是"我方内部原因"的一条独立路径，且完全不同于"策略配置变更"。**

## 二、我方全部可控动作清单

分析归因时，**'我方原因'必须收敛到下面这张表里的具体一项**，否则归因不完整。

| # | 动作 | 影响什么 | 责任方 | 典型可观测结果 |
|---|---|---|---|---|
| 1 | **基础出价调整** | 出价水平 | 获客运营 | 消耗、CPM、CPS 同步变化 |
| 2 | **RTA 出价系数调整**（W×Q 二维表） | 分客群出价 | 获客策略 | 特定客群规模/成本变化；大盘结构变化 |
| 3 | **RTA 排除规则变更** | 进入的人群集合 | 获客策略 | 人群结构变化、安全过件率变化 |
| 4 | **排除包更新** | 屏蔽特定设备/手机号集合 | 获客策略 | 部分人群消失 |
| 5 | **质量分阈值调整** | 进入的人群质量下限 | 获客策略 / 模型 | 安全过件率变化 |
| 6 | **模型版本上线**（preA/preG/额度） | 分档结果 | 获客模型 | 分档分布变化 → 人群结构变化 |
| 7 | **回传口径 / 门槛 / 分档配置调整** | 符合规则的回传样本量与结构 | 获客策略 | 规则覆盖率可能变化；后续 pCVR、CPS 是否变化须核验，不能用本环境发送成功率直接证明 |
| 8 | **预算调整** | 消耗上限 | 获客运营 | 消耗进度变化 |
| 9 | **定向 / 人群包调整** | 可触达人群规模 | 获客策略 | 曝光量、参竞率变化 |
| 10 | **素材上下线** | pCTR | 素材 / 运营 | CTR 变化 → 消耗与成本变化 |
| 11 | **风险审批口径（A卡/G卡阈值）** | 授信与动支 | 风险 | 授信率、安全过件率、动支率变化 |
| 12 | **额度策略 / 额度模型** | 授信额度 | 风险 / 额度策略 | 平均额度、额度使用率变化 |
| 13 | **资金路由 / 放款通道** | 发起→动支成功率 | 资金 / 研发 | 动支率骤降而发起数不变 |
| 14 | **产品流程 / 申请页 / 埋点** | 首登→申完 | 产品 / 数据 | 转化率变化 |

## 三、按症状定位动作（速查）

| 观测到的症状 | 优先排查 |
|---|---|
| 花费持平但授信数下降 | 首登量 / 首登成本 / 转化率（入口侧） |
| 首登持平但申完下降 | 产品申请流程、预授信提示、体验变更 |
| 申完持平但安全授信下降 | 人群质量（计费比 / 排除规则 / 质量分 / 风控口径） |
| 授信持平但发起下降 | 用户意愿、额度预期、竞品、产品改动 |
| 发起持平但动支下降 | 优先排查资金路由、放款通道、技术链路；同时核查发起后审批及数据口径 |
| 平均额度下降 + 额度使用率上升 | **额度策略 / 额度模型变更**（额度被下调，用户把额度打满） |
| 人均借款下降 + 平均额度不变 | 客群结构变化（小额需求用户流失） |
| 回传比例下降 | 本环境指标为应回传对象的发送成功率，先核发送链路；规则性排除需另取候选数和应回传数（见 04 文档 5.2） |
| 大盘正常但某子组严重恶化 | 局部结构问题（客群 / RTA 策略 / 账号 / 素材） |
| 消耗跑不出去 | 按 `eCPM = Bid × pCTR × pCVR` 穷举（见 07 文档） |
| 全渠道同时同幅异动 | **优先怀疑数据问题，而不是业务问题** |

## 四、阈值体系

### 4.1 当前告警阈值

见 03 文档 4.1 节。核心阈值：CPS > 0.54、安全过件率 < 17%、计费比 > 1.52、平均额度 < 29,000。

### 4.2 ⚠️ 阈值的四个已知问题

| # | 问题 | 影响 |
|---|---|---|
| 1 | **全局静态阈值，两个渠道共用** | 抖音平均额度基线 25,468 < 阈值 29,000，**若该指标可独立告警则抖音长期误报** |
| 2 | **只对结果指标生效**（CPS、安全过件率） | 过程指标（动支率、额度使用率、平均额度、回传比例）即使严重恶化，只要没传导到结果指标就**完全看不见** |
| 3 | **只做单日比对，无趋势视角** | "每天都没越线但 7 天累计恶化 15%"的慢变量**永远不会被告警** |
| 4 | **无形态识别** | 突变 / 渐进 / 断崖恢复三种形态对应完全不同的原因，但阈值判定一视同仁 |

### 4.3 改进方向（本环境内的推荐做法）

| 方向 | 做法 |
|---|---|
| 动态基线 | 阈值改为「渠道 × 时段」的历史分位数 |
| 过程指标独立告警 | 让过程指标也能独立触发，而不是只作为结果指标的附注 |
| 趋势检测 | 增加 7 日移动平均的斜率判定 |
| 形态识别 | 突变+稳定 / 渐进下滑 / 断崖+自行恢复 分别处理 |
| 结构体检 | 大盘正常时也执行子组扫描（结构与离散度） |
| 前置预警 | 回传比例、首登成本、素材 CTR 等前置信号进入独立预警通道 |

## 五、策略实验的设计与污染

### 5.1 相对干净的实验方式

**按设备 ID 分桶**：部分媒体支持按设备 ID 分桶并在请求维度告知广告主，广告主可按桶 ID 做 RTA 出价或策略分流。**这是本业务中最干净的实验方式。**

### 5.2 ⚠️ 容易受污染的实验类型

| 实验类型 | 主要污染来源 |
|---|---|
| 账户间实验 | 媒体在行业、主体、账户、计划、素材等层级都有模型预估，一个账户动作会影响其他账户 |
| 回传实验 | 改变部分账户回传会影响主体或行业模型，可能污染对照组 |
| 排除包实验 | 实验组排除后，对照组可能竞得更多原本被排除的人群 |
| 出价类型实验 | 系数出价与 CPA 出价拟合目标不同，账户间仍可能有人群竞得溢出 |

### 5.3 实验分析的最小要求

一次可信的策略效果评估，至少需要：

| # | 要素 | 说明 |
|---|---|---|
| 1 | **找到变更时点** | 从变更记录中定位 |
| 2 | **确定对照组** | 优先设备 ID 分桶；退而求其次用相邻客群 / 同期大盘 |
| 3 | **验证对照组是否干净** | 核查流量挤出与差异化处理；对照组后窗变化本身不等于污染 |
| 4 | **对照校正** | 明确使用加法 DID 还是相对变化之比，并检查前趋势与可比性；不能自动视为因果效应 |
| 5 | **核心指标 + 保护指标** | 核心：规模、CPS；保护：安全过件率、首借单产、逾期率 |
| 6 | **观察窗口与回滚条件** | 明确"什么情况下判定无效并回滚" |
| 7 | **区分相关性与因果** | 时间吻合不等于因果；需排除同期其他变更 |
