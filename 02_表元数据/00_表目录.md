## 二、表之间的关系

```text
                    ads_rta_media_daily  （媒体日级 · 大盘）
                              │
        ┌─────────────┬───────┴────────┬──────────────┐
        │             │                │              │
        ▼             ▼                ▼              ▼
 segment_daily   funnel_daily    quality_daily   delivery_daily
（按 RTA 策略/     （按客群分层）    （按 RTA 策略/    （按 RTA 策略/
  版位/账号/                       账号）         账号）
  客群分层切分）
        │
        ▼
 strategy_experiment （客群分层的子集：3W2Q / 3W3Q）

 creative_daily （抖音素材，与 media_daily 的花费/曝光/点击按份额对应）
```

### 关联键

| 关联 | 键 |
|---|---|
| 日级事实表 | `date`；变更日志使用 `变更日期` |
| 渠道相关表 | `media` |
| 细分表之间 | `media` + `segment_type` + `segment_name` |
| 漏斗表 ↔ 细分表 | `media` + `date` + `客群分层` = `segment_name`（当 `segment_type='客群分层'`） |
| 实验表 ↔ 细分表 | `media` + `date` + 客群映射（实验组=`3W2Q`，对照组=`3W3Q`，细分表须限定 `segment_type='客群分层'`） |
| 素材表 ↔ 媒体表 | 按 `date` 汇总素材表的花费/曝光/点击 = 抖音媒体日的对应值 |
| 变更日志 ↔ 日级事实表 | 用 `变更日期` 对齐 `date`，再核对 `变更对象`；同日可有多条记录，不能当作一对一事实表 JOIN 或完整生效证据 |

## 三、⚠️ 三条使用约定

### 3.1 细分的"切分"语义

`ads_rta_segment_daily` 中的 `segment_type` 是**同一大盘的多个独立切分**，不是交叉维度：

| `segment_type` | 归属渠道 | 说明 |
|---|---|---|
| `RTA策略` | 腾讯 | 4 个值，之和 = 腾讯大盘 |
| `版位` | 腾讯 | 4 个值，之和 = 腾讯大盘 |
| `客群分层` | 腾讯、抖音 | 5 个值，之和 = 对应渠道大盘 |
| `账号` | 抖音 | 4 个值，之和 = 抖音大盘 |

> ✅ **每一个 `segment_type` 的细分之和，都精确等于该渠道当日的大盘值。**
> ❌ **不要跨 `segment_type` 相加**（例如把"RTA 策略"和"版位"加起来）。

### 3.2 金额单位与格式

| 项 | 约定 |
|---|---|
| 金额 | 单位：人民币元，保留 2 位小数 |
| 计数 | 整数 |
| 比率 | 小数形式（0.4653 = 46.53%），不带百分号 |
| 日期 | `YYYY-MM-DD` |

### 3.3 时间窗口径

**转化人数及首借金额为首登 cohort 的 T0–T7 累计终值；花费、曝光、点击等投放字段按当日记录。** 详见 `01_知识库/03_核心指标口径.md`。

### 3.4 模拟字段与可验证边界

| 字段 / 问题 | 本环境的边界 |
|---|---|
| 安全授信 | 按授信环节 A 卡前 3 组解释；仅有汇总人数，没有 A 卡分组或用户明细 |
| `转化数` 与 `pCVR` | 前者在媒体表为动支数；后者在投放表按同细分的授信数 ÷ 点击加扰动构造，目标不同 |
| 回传与竞价 | 有 `回传比例`、`参竞率` 等模拟比率，没有应回传数、成功回传数、请求数、参竞次数、竞得次数；不能独立复算或完整拆解流量损失 |
| 素材与账号 | 素材表仅有抖音日期 × 素材数据，没有素材 × 账号或素材 × RTA 策略的交叉明细 |
| 策略实验 | 3W2Q 与 3W3Q 是不同客群，不是随机分桶；变更后效果需检查前趋势、同期变更与流量挤出 |

## 四、派生指标的计算位置

本环境的数据表**只存基础量与少量比率字段**，绝大多数指标需要派生计算：

| 指标 | 计算方式 |
|---|---|
| CPS | `花费 ÷ 首借金额` |
| 授信成本 | `花费 ÷ 授信数` |
| 授信单产 | `首借金额 ÷ 授信数` |
| cpcl | `花费 ÷ 授信额度合计` |
| 安全过件率 | `安全授信数 ÷ 申完数` |
| 动支率 | `动支数 ÷ 授信数` |
| 发起率 | `发起数 ÷ 授信数` |
| 发起→动支率 | `动支数 ÷ 发起数` |
| 平均授信额度 | `授信额度合计 ÷ 授信数` |
| 额度使用率 | `(首借金额 ÷ 动支数) ÷ (授信额度合计 ÷ 授信数)` |
| 人均借款 | `首借金额 ÷ 动支数` |
| 转化成本 | `花费 ÷ 转化数` |
| 计费比 | `转化成本 ÷ 基础出价` |
| 首登成本 | `花费 ÷ 首登数` |
| CPM | `花费 ÷ 曝光 × 1000` |
| CTR | `点击 ÷ 曝光` |
| 消耗进度（delivery 表） | `消耗 ÷ 均分预算参考值`——⚠️ 该分母是均分参考值，**不代表真实预算** |
| 安全交易占比 | `安全首借金额 ÷ 首借金额` |
