# `ads_rta_funnel_daily` · 漏斗转化日级表

| 项 | 内容 |
|---|---|
| **表名** | `ads_rta_funnel_daily` |
| **中文名** | 漏斗转化日级表 |
| **粒度** | `date` × `media` × `客群分层` |
| **主键** | 上述三字段 |
| **行数** | 560（56 天 × 2 渠道 × 5 客群） |
| **文件** | `03_模拟数据/ads_rta_funnel_daily.csv` |
| **用途** | 逐环节转化率分析、漏斗断点定位、动支率两段分解 |

---

## 字段说明

### 量级字段

| 字段 | 含义 |
|---|---|
| `曝光` / `点击` | 各级量级（= `ads_rta_segment_daily` 中同客群的值） |
| `首登数` / `申完数` / `授信数` / `发起数` / `动支数` | 漏斗各级人数 |

> ⚠️ 本表**不含** `安全授信数`（安全授信是授信的子集，不构成漏斗环节）。需要安全数据请查 `ads_rta_quality_daily` 或 `ads_rta_segment_daily`。

### 转化率字段（本表的核心价值）

| 字段 | 计算 | 说明 |
|---|---|---|
| `曝光点击率` | 点击 ÷ 曝光 | 素材与定向吸引力 |
| `点击首登率` | 首登 ÷ 点击 | **承接链路效率**（落地页、唤起、埋点） |
| `首登申完率` | 申完 ÷ 首登 | 产品申请流程体验 |
| `申完授信率` | 授信 ÷ 申完 | 风险审批口径 |
| **`授信发起率`** | 发起 ÷ 授信 | **用户借款意愿** |
| **`发起动支率`** | 动支 ÷ 发起 | **执行链路成功率** |

---

## ⭐ 核心用法：动支率两段分解

```text
动支率 = 授信发起率 × 发起动支率
```

**这是变现类问题（"用户拿到授信后不借钱"）的核心分析骨架。**

| 观测 | 结论 |
|---|---|
| 发起率正常、发起动支率骤降 | **执行链路故障**（资金路由 / 放款通道 / 技术） |
| 发起率下降、发起动支率正常 | 用户意愿问题（额度预期 / 竞品 / 产品流程） |

> ⭐ **`发起动支率` 的正常水平是 95%+。** 这个环节几乎没有失败空间，因此**任何显著下跌都不存在良性解释**。

| 方向 | 说明 |
|---|---|
| **上游** | 与 `ads_rta_segment_daily` 的 `客群分层` 行完全一致 |

## ⚠️ 使用注意

| # | 注意 |
|---|---|
| 1 | **按 `media` + `date` 汇总 5 个客群，即等于该渠道大盘的漏斗。** 可与 `ads_rta_media_daily` 交叉验证 |
| 2 | 本表**不含曝光前的竞价环节**（参竞率、请求量）。要分析"为什么拿不到曝光"需结合 `ads_rta_delivery_daily` |
| 3 | **`点击首登率` 的口径依赖"点击"的定义。** 本环境的"点击"是素材级广告点击（见 03 文档）。若与其他系统的"点击"对比，量级不可比 |
| 4 | 小客群的日级比率指标噪音较大（如 `3W2Q` 在腾讯侧日申完约 34 人），**建议用 7 天窗口聚合后再比较** |
