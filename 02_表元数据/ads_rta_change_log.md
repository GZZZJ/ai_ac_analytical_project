# `ads_rta_change_log` · 变更日志

| 项 | 内容 |
|---|---|
| **表名** | `ads_rta_change_log` |
| **中文名** | 变更日志 |
| **粒度** | 变更事件 |
| **主键** | `变更日期` + `变更时间` + `变更对象` |
| **行数** | 23 |
| **文件** | `03_模拟数据/ads_rta_change_log.csv` |
| **用途** | 归因时对照变更记录、定位变更时点 |

---

## 字段说明

| 字段 | 类型 | 含义 |
|---|---|---|
| `变更日期` | 日期 | 记录的操作日期，可与其他表的 `date` 对齐；不保证当日完整生效 |
| `变更时间` | 时间 | 记录的操作时点，不保证为效果出现的时点 |
| `变更类型` | 字符串 | `素材上线` / `素材下线` / `预算调整` / `定向调整` / `排除包更新` / `模型上线` / `RTA出价系数调整` / `回传规则复核` / `回传链路异常` / `回传链路恢复` |
| `变更对象` | 字符串 | 渠道 + 具体对象（如 `腾讯-腾讯RTA策略_A`、`抖音-授信账户-常规`） |
| `变更前` / `变更后` | 字符串 | 变更内容 |
| `操作方` | 字符串 | 责任方 |
| `备注` | 字符串 | 操作方填写的意图说明 |

---

## ⚠️ 三条使用原则

### 1. 时间吻合 ≠ 因果

同一时期可能存在多个变更；也可能存在"变更了但没有效果"的情况。

| ❌ 错误读法 | ✅ 正确读法 |
|---|---|
| "X 日有变更，所以指标异常了" | "X 日有变更；数据显示该对象的指标与变更方向一致；需进一步验证净效应" |

### 2. `备注` 是操作方的意图描述，不是事实结论

例如"为 Q4 冲量预留额度"说明的是**为什么做**，不是**做了什么效果**。判断效果要看数据。

### 3. 本表记录主动操作及链路异常、恢复事件

以下事件**不会**出现在本表中，但同样重要：

| 类型 | 如何发现 |
|---|---|
| 素材 CTR 自然衰减 | `ads_rta_creative_daily` 的 CTR × 上线天数关系 |
| 素材供给空窗 | 在投素材数与上线日期分布 |
| 大盘竞价环境变化 | CPM 趋势 + 自身出价是否变化 |
| 承接链路渐进劣化 | 转化率的持续趋势 |
| **客群结构漂移** | **子组份额变化（无任何变更记录）** |

> ⭐ **最后一条尤其重要**：当**各子组指标都正常、但大盘指标异常**时，问题往往在"结构"而非"个体"，而结构变化不会出现在任何变更记录中。

## 本环境的变更时间分布

| 时段 | 事件密度 | 说明 |
|---|---|---|
| 2026-07-29 ~ 08-28 | 8 条 | 素材例行轮换为主，每约 6 天 1 条 |
| 2026-09-03 ~ 09-12 | 7 条 | 素材、预算、定向、排除包、模型、回传 |
| **2026-09-14 ~ 09-16** | **5 条** | **密集区：模型上线、系数调整 ×2、预算调整 ×2，涉及 3 个责任方** |
| 2026-09-19 ~ 09-22 | 4 条 | 素材上线、回传异常与恢复、定向调整 |

> ⚠️ **9 月 14–16 日的变更密集区是归因上的多重候选区。** 分析时必须逐条与数据核对，而不是挑一个最顺眼的。

## ⚠️ 使用注意

| # | 注意 |
|---|---|
| 1 | 本表**不包含腾讯侧的素材信息**（本环境的素材数据只有抖音） |
| 2 | `变更时间` 为时点信息，但数据是**日级**的。**同一天内的多次变更无法在数据上区分先后** |
| 3 | 变更的**实际生效**可能有爬坡（如出价系数调整、素材上线），**不代表变更日当天即达到完整效果** |
| 4 | 本表中 `2026-09-07` 的"回传规则复核"**未变更实质门槛**，仅为例行复核记录 |
