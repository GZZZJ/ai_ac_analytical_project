## 字段说明

| 字段 | 类型 | 含义 | 口径 / 计算 |
|---|---|---|---|
| `date` | 日期 | 数据日期 | `YYYY-MM-DD` |
| `media` | 字符串 | 媒体渠道 | `腾讯` / `抖音` |
| `花费` | 金额 | 当日投放花费 | 业务口径（不含返点、返货、赔付） |
| `曝光` | 整数 | 广告曝光次数 | — |
| `点击` | 整数 | 广告点击次数 | **素材级广告点击**（见 03 文档口径风险） |
| `首登数` | 整数 | 首次登录 App/小程序的人数 | T0–T7 |
| `申完数` | 整数 | 提交借款申请的人数 | T0–T7 |
| `授信数` | 整数 | 通过贷前审批并获得额度的人数 | T0–T7 |
| `安全授信数` | 整数 | 授信环节 **A 卡分组前 3 组**的授信人数 | **授信的子集，非漏斗环节**；安全过件率的分母为申完数 |
| `发起数` | 整数 | 授信后发起借款申请的人数 | T0–T7 |
| `动支数` | 整数 | 借款成功到账的人数（= 首借人数） | T0–T7 |
| `首借金额` | 金额 | 首次借款交易金额合计 | T0–T7 |
| `授信额度合计` | 金额 | 授信用户获得的额度总和 | 用于计算平均额度与 cpcl |
| `安全首借金额` | 金额 | 安全用户产生的首借金额 | 用于计算安全交易占比 |
| `转化数` | 整数 | 本环境用于计算转化成本、计费比的模拟转化数 | **= 动支数**；与投放表 `pCVR` 的模拟授信目标不同 |
| `回传比例` | 比率 | 模拟的“回传成功数 ÷ 应回传数” | 直接构造的 0–1 比例；本表没有原始计数，无法复算，也不是规则覆盖率 |
| `回传比例变化幅度` | 比率 | 本日回传比例 − 前一日回传比例 | 首日为空白 |
| `基础出价` | 金额 | 计划层基础出价 | 本环境全期固定 |
| `参竞率` | 比率 | 参竞次数 ÷ 请求次数 | 0–1 |
| `日预算` | 金额 | 渠道日预算上限 | — |

## 常用派生指标

见 `00_表目录.md` 第四节。最核心的三个恒等式：

```text
CPS = 花费 ÷ 首借金额 = 授信成本 ÷ 授信单产
授信单产 = 平均授信额度 × 额度使用率 × 动支率
动支率 = 授信发起率 × 发起动支率
```

## ⚠️ 使用注意

| # | 注意 |
|---|---|
| 1 | **`转化数` = `动支数`。** 这是本环境的口径定义。计费比 = `花费 ÷ 转化数 ÷ 基础出价`，因此**转化数下降会机械性推高计费比**——判断"媒体侧问题"前必须先排除这个原因 |
| 2 | **`安全授信数` 不是漏斗上的一环**，它是 `授信数` 的子集。漏斗应写成：曝光 ≥ 点击 ≥ 首登 ≥ 申完 ≥ 授信 ≥ 发起 ≥ 动支；另有 安全授信 ≤ 授信 |
| 3 | **两个渠道量级不同**（稳定期腾讯日授信约 161、日花费约 37.4 万；抖音约 229、40.2 万）。跨渠道应同时看规模与分母一致的比率，不能只比较绝对值 |
| 4 | **计费比仅对腾讯适用**，抖音侧的计费比虽在投放表中存在，但**不应用于判定** |
| 5 | `回传比例变化幅度` 首日为空白字符串 |
| 6 | `回传比例` 独立构造，未按额度档、模型分箱或发送明细生成；可描述模拟波动，不能据此证明规则覆盖率变化或回传对 `pCVR`、CPS 的因果影响 |
